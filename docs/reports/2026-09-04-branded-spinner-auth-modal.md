## 1. 💡 الشرح النظري وتجربة المستخدم (Theoretical & Conceptual Overview)

### 🎯 الهدف والدافع (Purpose & Motivation)
الهدف الأساسي من هذا التعديل هو توحيد لغة التصميم والهوية البصرية (Visual Brand Identity) عبر كافة واجهات منصة هارفستا. في التحديثات السابقة، كان التبديل بين نماذج المصادقة (تسجيل الدخول، إنشاء حساب، نسيت كلمة المرور) يستخدم سبينر CSS دائرياً تقليدياً وبسيطاً للغاية، بينما تمتلك المنصة سبينراً استثنائياً وفاخراً في صفحة تحميل تفاصيل المنتجات (`PageLoader`) يدمج درع هارفستا القرمزي، بتلات الزهور الذهبية والخضراء، والمدار الخارجي الدوار. طلب المستخدم استبدال السبينر التقليدي بهذا السبينر الأيقوني المخصص ليعمل بدقة ونقاء في نافذة المصادقة أثناء التبديل.

### 🌟 لماذا قمنا بهذا التعديل (Why This Change Matters)
1. **تعزيز الانطباع الاحترافي والفخامة:** السبينر التقليدي يعطي شعوراً بأنه مكون مؤقت (Default Placeholder)، بينما السبينر المخصص يعزز هوية العلامة التجارية ويمنح المستخدم شعوراً بالثقة والجودة في كل تفاعل.
2. **اتساق تجربة المستخدم (UI/UX Consistency):** توحيد مكونات التحميل يجعل التطبيق يبدو ككتلة واحدة متماسكة ومصممة بعناية فائقة.
3. **تغذية بصرية سلسة (Visual Feedback):** خلال فترة الانتظار المقررة (1 ثانية)، يرى المستخدم شعار المنصة النابض وحركة النقاط الثلاث المتناغمة مع عبارة "جاري التحميل..."، مما يحول فترة التحميل القصيرة من مجرد توقف مؤقت إلى حركة انتقالية جمالية ومريحة للعين.

### 👁️ النتيجة المتوقعة وسيناريو الاستخدام (Expected Behavior & Outcomes)
- عند فتح نافذة تسجيل الدخول والنقر على "نسيت كلمة المرور؟" أو "إنشاء حساب جديد"، يبدأ مؤقت الانتقال لمدة 1000ms.
- يختفي النموذج السابق بسلاسة، ويظهر في قلب المودال سبينر هارفستا المخصص:
  - حلقة خارجية دوارة ذات مدار قرمزي أنيق (`animate-spin`).
  - شعار الوردة والدرع القرمزي في المنتصف بتدرجات ذهبية وخضراء نابضة (`animate-pulse`).
  - نص "جاري التحميل..." بتدرج لوني أنيق تتبعه 3 نقاط قفازة (`animate-bounce`).
- بعد انقضاء الثانية، ينساب النموذج المستهدف في مكانه مع الحفاظ التام على الأبعاد المتناسبة للنافذة دون أي تشوه أو قفز مفاجئ في الارتفاع.
- يعمل السبينر بكفاءة وجمالية متكافئة في كل من الوضع الفاتح (Light Mode) والوضع المظلم (Dark Mode).

## 2. 🔬 التشريح والشرح التقني العميق (In-Depth Technical Architecture & Code Breakdown)

### 📁 تفنيد الملفات وتفاصيل التعديل الهندسي

#### 1. [`PageLoader.tsx`](file:///e:/laragon/www/harvesta/resources/frontend/src/components/PageLoader.tsx)
- **الدافع التقني:** كان المكون مصمماً في الأصل كشاشة تحميل كاملة (`min-h-[70vh]` أو `py-16`) بدون خيارات للتحكم في الحجم الخارجي أو الهوامش عند استخدامه داخل المودالات الضيقة.
- **التعديلات الهندسية المنفذة:**
  1. **توسيع الواجهة `PageLoaderProps`:**
     ```typescript
     interface PageLoaderProps {
       message?: string;
       subMessage?: string;
       fullScreen?: boolean;
       className?: string;       // سماح بتمرير فئات تنسيق مخصصة للحاوية
       size?: 'sm' | 'md' | 'lg'; // نظام تحجيم مرن للمكون
     }
     ```
  2. **نظام التحجيم المتدرج (Scalable Size Matrix):**
     تمت إضافة قاموس أحجام ذكي `sizeStyles`:
     - `sm`: حلقة `w-16 h-16`، وشعار `w-8 h-8`، ومسافة `mb-4`، وخط `text-sm font-semibold`.
     - `md` (الافتراضي): حلقة `w-20 h-20 sm:w-24 sm:h-24`، وشعار `w-10 h-10 sm:w-12 sm:h-12`، ومسافة `mb-6`، وخط `text-sm sm:text-base font-bold`.
     - `lg`: حلقة `w-24 h-24 sm:w-28 sm:h-28`، وشعار `w-12 h-12 sm:w-14 sm:h-14`، ومسافة `mb-8`.
  3. **التوافق العكسي بنسبة 100% (Zero-Breaking Backward Compatibility):**
     تم ضبط `size = 'md'` كقيمة افتراضية، مما يضمن أن جميع الاستخدامات السابقة في المنصة (مثل صفحة تفاصيل المنتج `ShowProduct.tsx` وحارس التوجيه `DashboardAuthRoute.tsx`) تحتفظ بحجمها وتنسيقها دون أدنى تغيير جانبي.
  4. **مرونة الحاوية:**
     إذا تم تمرير `className`، فإنه يحظى بالأولوية ليحل محل هوامش الشاشة الكاملة، مما أتاح استخدامه بنعومة داخل المودال عبر فئات مثل `py-6 sm:py-8`.

#### 2. [`LoginPrompt.tsx`](file:///e:/laragon/www/harvesta/resources/frontend/src/components/LoginPrompt.tsx)
- **الدافع التقني:** استبدال عنصر الـ div البدائي الذي كان يحتوي على سبينر CSS ذي حدود حمراء بمكون `PageLoader` ذي الهوية المؤسسية.
- **التعديلات الهندسية المنفذة:**
  1. استيراد المكون المطور:
     ```typescript
     import PageLoader from './PageLoader';
     ```
  2. تحديث كتلة الحالة الانتقالية `isFormTransitioning`:
     ```tsx
     <AnimatePresence mode="wait" initial={false}>
       {isFormTransitioning ? (
         <motion.div
           key="form-transition-spinner"
           className="w-full flex items-center justify-center"
           initial={{ opacity: 0, scale: 0.94 }}
           animate={{ opacity: 1, scale: 1 }}
           exit={{ opacity: 0, scale: 0.94 }}
           transition={{ duration: 0.15 }}
         >
           <PageLoader
             fullScreen={false}
             size="md"
             className="py-6 sm:py-8"
             message={t('common:loading', 'جاري التحميل...')}
           />
         </motion.div>
       ) : ...
     ```
  3. **تناغم الارتفاع مع الـ Framer Motion Layout:**
     بفضل استخدام `className="py-6 sm:py-8"` مع حجم `size="md"`، يبلغ الارتفاع الإجمالي لكتلة التحميل حوالي `175px`، وهو رقم يقع في المنتصف الهندسي الدقيق بين ارتفاع نموذج نسيت كلمة المرور (~140px) وارتفاع نموذج تسجيل الدخول (~220px). هذا التناغم يمنع حدوث قفزات عنيفة في ارتفاع النافذة، مما يجعل حركة `motion.div layout` تبدو غاية في النعومة والانسيابية.

### 🎨 دعم الثيم الثنائي (Dual Theme Support - Light & Dark Mode)
تم الحفاظ على التوافق الصارم مع متطلبات النمطين الفاتح والمظلم:
| العنصر | في الوضع الفاتح (Light Mode) | في الوضع المظلم (Dark Mode) |
| :--- | :--- | :--- |
| الحلقة الدوارة (Outer Ring) | `border-t-[#B12C2E] border-r-[#B12C2E]/60` | `dark:border-t-[#E03E41] dark:border-r-[#E03E41]/60` |
| تدرج نص التحميل | `from-gray-900 via-gray-700 to-gray-900` | `dark:from-slate-100 dark:via-slate-300 dark:to-slate-100` |
| النقاط الثلاث القافزة | `bg-[#B12C2E]` | `dark:bg-[#E03E41]` |
| النص الفرعي | `text-gray-400` | `dark:text-slate-500` |
| خلفية المودال والحواف | `bg-white border-gray-100` | `dark:bg-[#151D2C] dark:border-slate-800` |

### 🛡️ التحقق ومعالجة الحالات الحدية (Edge Cases & Safety)
1. **منع تصادم معرفات الـ SVG (Gradient Defs):**
   تعتمد التدرجات اللونية للشعار على `linearGradient` بمعرفات موحدة، وتعمل داخل بيئة الـ DOM كمرجع عام آمن دون استهلاك ذاكرة إضافي.
2. **التحقق من سلامة الأنواع البرمجية (Type Checking):**
   تم تشغيل فاحص الأنواع `npx tsc --noEmit` واجتاز الفحص بنجاح تام (Exit code: 0) دون أي أخطاء أو تحذيرات.
3. **تزامن الـ Animation Lifecycle:**
   تم ضبط `initial={false}` و `mode="wait"` في `AnimatePresence` لضمان عدم حدوث تداخل بين حركة خروج السبينر ودخول النموذج الجديد.
